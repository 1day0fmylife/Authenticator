# CLAUDE.md — инструкции для Claude Code

Это дополнение к [AGENTS.md](AGENTS.md). **Все ограничения AGENTS.md, PLAN.md и принятых ADR обязательны.** Приоритет проекта — безопасность, независимость от поставщиков и минимальный проверяемый supply chain, а не скорость добавления функциональности.

## Контекст

Проект Authenticator находится на стадии формирования архитектуры:

- P0: десктопный Authenticator под Windows и Ubuntu на **Rust** (local/offline TOTP/HOTP, encrypted vault).
- P0: отдельный Go MFA-verifier для других собственных приложений, не зависящий от конкретного IAM и клиентского GUI.
- P1: проверяемые сборки и релизы, экспорт/восстановление, интеграция через OpenAPI.
- P2: дополнительный OS unlock/WebAuthn/E2EE sync только по ADR.
- P3: мобильные клиенты — не реализовывать сейчас.

## Обязательный рабочий цикл

1. Прочитать README.md → PLAN.md → TODO.md → AGENTS.md.
2. Перед кодом назвать TODO ID, входные/выходные контракты, trust boundary, новые зависимости и критерии приёмки.
3. Если нужен GUI framework, сначала выполнить GUI Dependency Gate и подготовить ADR, а не автоматически выбрать Qt, Tauri, egui, Slint или Electron.
4. Если нужен cryptographic crate, сначала оформить решение по KDF/AEAD/nonce/AAD/secret lifetime; **не писать самодельную криптографию**.
5. Реализовать минимальный вертикальный срез, затем тесты негативных случаев и отказов.
6. После работы указать, какие команды действительно запускались и какие проверки не выполнены. Обновлять чекбокс TODO только по факту.

## Особые запреты

- Не добавлять обязательные облачные сервисы, аккаунты, аналитику, Electron/Node runtime и сети в desktop.
- Не связывать генерацию TOTP с сервером verifier; каждый компонент независим.
- Не записывать ключи, seed, OTP или recovery codes в logs, examples или PR.
- Не вводить ORM/Redis/несогласованные Go или Rust dependency.
- Не делать auth bypass при недоступном verifier, не принимать от браузера «MFA verified».
- Не выводить «production-ready», «прошло аудит» и «reproducible» без свидетельств.
